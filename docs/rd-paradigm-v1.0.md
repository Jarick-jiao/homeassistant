# HomeMate 研发范式 v1.0

> 本文件是 HomeMate 工程的最高研发约束，描述「需求如何变成代码、代码如何组织、人机如何协作」。
> 所有对 `internal/`、`web/`、`scripts/`、`cmd/`、`mcp-servers/`、`docs/` 的修改必须遵守。
> 版本：v1.0（2026-09-05），范式本身的演进走「文档变更」流程（见 §4）。

---

## 1. 规范驱动流程（Spec-Driven Development）

### 1.1 单一事实来源

| 文档 | 角色 | 更新时机 |
|------|------|----------|
| `docs/vX.Y-PRD.md` | 产品**现状**与**目标**的唯一事实来源 | 每次功能变更同一 PR 内更新 |
| `docs/rd-paradigm-vX.Y.md` | 研发范式（本文件） | 流程/架构约定变化时 |
| `docs/fix-reports/*.md` | 问题修复归档 | 修复批次完成时 |
| 代码 | 实现事实来源 | —— |

**铁律：PRD 与代码不一致时，以代码为「现状事实」修订 PRD，禁止让 PRD 描述不存在的架构。**
v3.x 时期 PRD 写 PostgreSQL/React/cmd-server，而代码是 SQLite/内嵌静态页/cmd-homemate，此类漂移视为事故。

### 1.2 需求流转四阶段

```
PRD（是什么/为什么） → 任务拆解（做什么，原子可提交） → 编码（按架构约定） → 验收（门禁+核对清单）
```

1. **PRD**：新功能先在 PRD 中写明：用户场景、接口契约（方法/路径/鉴权/请求/响应）、数据模型（表/字段/索引）、状态机（状态集合+合法迁移+触发源）、边界与错误码。
2. **任务拆解**：一个任务 = 一次可独立提交的完整变更（含代码+测试+PRD 同步），禁止「大爆炸式」提交。
3. **编码**：遵循 §2 架构约定。
4. **验收**：§3 门禁全绿 + §2.10 评审清单逐项过。

### 1.3 状态机必须显式登记

凡涉及状态字段（家务认领、兑换记录、提醒、调度任务……），必须在 PRD 或代码注释中维护：

- 状态全集（如 `pending → completed → confirmed`）
- 合法迁移表（当前状态 × 触发源 → 目标状态）
- 非法迁移的处理（返回 4xx，禁止静默成功）
- 死状态检查：不允许存在「只能写入、永远无法迁出」的状态。

### 1.4 接口契约先行

路由注册即契约。每个接口在 PRD 中登记：鉴权要求（公开/JWT/管理员/API Token）、属主校验要求、请求体、成功响应、错误响应。
**禁止**出现「注释写仅管理员、实际挂在公开路由组」这类注释与代码不符的情况。

## 2. 架构与编码约定

### 2.1 分层架构

```
cmd/homemate        进程入口：装配依赖、启动/优雅关闭，不写业务逻辑
internal/router     路由与中间件注册：只做「URL → handler」映射与鉴权挂载
internal/handler    HTTP 层：参数解析/校验、身份解析、调用 store/service、组装响应
internal/service    领域服务：调度器、外部客户端、算法、跨表业务编排
internal/store      数据访问：SQL 只出现在这一层；handler/service 不写裸 SQL
internal/model      数据结构：DB 模型与 API 视图分离（XxxDB / XxxView）
internal/pkg        通用工具（jwt/response）
mcp-servers         独立 MCP 进程
scripts             外部同步脚本（Python，经调度器 exec 调用）
```

- 依赖方向：`handler → service → store`，禁止反向依赖、禁止跨层（handler 直接拼 SQL）。
- 公共能力放 `internal/pkg` 或对应 service 包，禁止 handler 包间横向依赖。

### 2.2 身份与授权（最高优先级约定）

1. **认证身份只来自 JWT**：`userID / username / role / isAdmin` 由 AuthMiddleware 注入 context。
2. **业务身份禁止由请求体传入**：`member_id / member_name / confirmer / voter` 等「我是谁」字段一律由后端从 JWT 解析：
   - 登录用户 → `users.id` → `family_members.user_id` 解析出家庭成员；
   - 未绑定家庭成员的账号调用家庭业务接口，返回 403「未绑定家庭成员」；
   - 管理员代操作场景必须走独立管理员接口并显式传目标 id，不允许混在普通接口里。
3. **授权三级模型**：
   - 公开接口：明确列在 PRD 公开清单（大屏/新闻/纪念日只读）；
   - 登录接口：AuthMiddleware；
   - 管理员接口：`RequireAdmin()`，无例外。
4. **资源属主校验**：操作他人资源（投票/认领/兑换/档案）必须校验属主，返回 403 而非 404。
5. 新增路由时，同步在 PRD 接口表登记鉴权级别。

### 2.3 数据模型约定

1. **外键用 ID，不用名字字符串**：关联家庭成员一律存 `member_id INTEGER`；`member_name` 仅作展示冗余。历史按名字关联的表逐步加列、回填、双写过渡后切换。
2. **改名安全**：任何按名字 JOIN 的统计都视为缺陷。
3. **金额/积分类数据用流水表**：余额 = 流水求和（含负向流水），禁止只存「当前值」；兑换/扣减必须写负向流水并在同一事务内校验余额充足。
4. **累计型资产不做 TTL 清理**：积分流水等属于用户资产，不进入归档清理 TTL；TTL 只适用于消息/通知/日志类时效性数据。
5. **迁移幂等**：`ALTER` 前用 `pragma_table_info` 检查列存在；唯一索引创建失败要兜底处理历史脏数据。
6. **删除策略**：业务数据优先软删除（`is_active`）；硬删除需评估关联数据（users 账号、积分流水）并在 PRD 说明。
7. SQLite DSN 必须开启 `_busy_timeout`；多写场景依赖 WAL。

### 2.4 时间与时区

1. 存储：`DATETIME` 统一按**本地时间字符串**写入（与既有 `datetime('now')`、Go `time.Now()` 直写一致）。
2. 解析用户输入的本地时间字符串（`"2006-01-02 15:04"`、`"2006-01-02"`）**必须**用 `time.ParseInLocation(layout, s, time.Local)`；禁止 `time.Parse`（按 UTC 解析，国内会偏 8 小时）。
3. RFC3339 带时区偏移的字符串可用 `time.Parse`。
4. 跨天判断（本周/今日）统一用 SQLite `date('now')` 或 Go `time.Now()` 本地时间，口径在同一功能内保持一致。

### 2.5 API 响应与错误处理

- 统一走 `internal/pkg/response`：成功 `code=0`，参数错误 400，未认证 401，无权限 403，不存在 404，冲突 409，服务器错误 500。
- **DB 操作失败必须返回错误响应**，禁止「失败也回 200 + 原样返回请求体」。
- 错误信息面向用户可理解；内部错误（SQL/外部 API）记日志，不把原始错误外泄。
- handler 中 `c.Get("db")` 取依赖失败时返回 500，不允许静默降级为空数据（除明确设计为公开只读的大屏接口）。

### 2.6 外部输入校验

- 所有写接口 `ShouldBindJSON` + `binding:"required"`；枚举值（role/status/category）必须白名单校验。
- 文件上传：扩展名白名单 + 大小限制 + **文件名只取 `filepath.Base`**（防路径穿越），存储名用 hash 前缀。
- 外部写入接口（`/api/external/*`）一律 API Token + scope 校验。
- WebSocket/微信回调等非标准入口：校验 Origin/签名，不提供伪造空间。

### 2.7 配置与密钥

- 配置入口：`config.yaml` + `HOMEMATE_*` 环境变量；命令行参数必须真正生效（如 `-config`）。
- 密钥禁止硬编码兜底长期使用；默认 JWT secret 仅允许首次启动引导，启动日志必须告警。
- 第三方凭证（Garmin/WeCom webhook）DB 存储时接口返回必须脱敏；运行时可改的配置必须对所有使用方即时生效（禁止启动时快照后不再刷新）。
- 执行外部脚本（Python sync）：路径转绝对、超时受控、环境变量白名单注入。

### 2.8 调度器约定

- 任务注册表（taskRegistry）是任务的唯一清单：名称、中文名、间隔、启用状态。
- **任务执行结果必须如实上报**：`recordRun(name, err)` 在任务结束时以真实 error 调用，禁止开头先记 success。
- 启停/间隔配置运行时可改即热生效；不能热生效的字段禁止在状态接口展示为已生效。
- 定点任务（每日/每周）用「ticker 细粒度轮询 + 当日已执行标记」，窗口判断与去重标记成对出现。
- 手动触发与定时触发走同一个执行函数。

### 2.9 占位实现的管理

- 未接入真实能力的功能（AI 对话、AI 分析等）必须：①接口/日志显式标注「占位」；②PRD 标注状态为「规划中」；③禁止生成以假乱真的持久化数据（如模板 AI 报告）。
- 占位转真实实现是一个独立任务，完成后删除占位标注。

### 2.10 提交前评审清单（Definition of Done）

- [ ] 新路由已在 PRD 登记鉴权级别与契约
- [ ] 「我是谁」类字段全部来自 JWT，无请求体信任
- [ ] 状态迁移有合法集校验，无死状态
- [ ] 时间解析使用 ParseInLocation
- [ ] 关联字段用 ID 不用名字；积分类变动有流水
- [ ] DB 失败路径返回错误而非 200
- [ ] 文件/外部输入有校验，文件名无穿越
- [ ] 调度任务状态如实记录
- [ ] PRD 与代码同步更新
- [ ] `go build ./...` && `go vet ./...` 全绿

## 3. AI 协作工作流

### 3.1 强制收尾流程（来自 `.trae/rules/agent-workflow.md`）

每组代码修改按序执行，禁止跳步：

```bash
go build ./...        # 1. 编译通过
go vet ./...          # 2. 静态检查通过
git add -A            # 3. 暂存
git commit -m "<type>(<scope>): <subject>"   # 4. Conventional Commits
git push              # 5. 必须推送，仅 commit 不 push 视为未完成
```

- build/vet 失败禁止 commit，修复后从第 1 步重来。
- 纯文档修改可跳过 build/vet，仍须 commit + push。
- **原子提交**：一个独立任务一次提交一次推送；提交信息示例：
  - `fix(auth): 注册接口收归管理员并接入 RequireAdmin`
  - `refactor(store): points_records 增加 member_id 并回填历史数据`
  - `docs: 新增研发范式 v1.0 与 v4.0 PRD`

### 3.2 AI 执行任务的边界

1. **评审/诊断类任务**：先输出分优先级的问题清单，经确认后再改代码；禁止未授权大规模重构。
2. **修改类任务**：先读后改——必须读取真实代码确认签名/结构，禁止凭假设编造调用。
3. **不臆造**：不存在的文件、接口、依赖、执行结果不得写进结论或文档。
4. **不顺手扩大范围**：任务外的坏味道记录到「后续任务」，不在当前提交夹带。
5. **用户未明确要求不创建文档**；范式/PRD 类文档经确认后落盘于 `docs/`。

### 3.3 任务协作节奏

- 复杂任务先给计划（TodoList）：任务序列、依赖顺序、验证方式。
- 每完成一个原子任务：跑门禁 → 提交 → 推送 → 简报，再进入下一个。
- 遇到契约级决策（接口形态、数据模型变更）暂停并给出选项，确认后继续。

### 3.4 文档版本规则

- PRD/范式版本号：`v主.次`；架构/契约不兼容变更升主版本，增量功能升次版本。
- 旧版 PRD 保留存档（`docs/v3.x-PRD.md` 不删），新版头部写明「替代 vX.Y」与变更摘要。
- 每次发版/批次修复在 PRD 末尾维护「变更记录」表。
