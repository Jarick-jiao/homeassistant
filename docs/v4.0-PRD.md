## 1. 产品概述

HomeMate 是面向单个家庭的智能生活助理服务端，围绕「家庭成员」提供：

- 健康数据管理（Garmin 同步、自定义指标、健康档案上传与 AI 分析入口）
- 家庭协作（家务认领/验收积分、积分兑换、留言板、通知提醒）
- 生活规划（日历日程与提醒、周末休闲方案投票、出行计划、纪念日）
- 信息聚合（时事新闻、天气、大屏仪表盘）
- 外部写入（微信/企业微信、MCP 生态、API Token 集成）

部署形态：单个 Go 二进制 + SQLite 数据文件 + 内嵌静态前端（`web/`），macOS/Linux 均可运行；Garmin/Apple 日历同步通过 `scripts/` 下 Python 脚本由调度器 exec 调用。

## 2. 技术架构（现状事实）

| 层 | 技术 | 说明 |
|----|------|------|
| 入口 | `cmd/homemate` | 装配 DB/客户端/调度器/路由，优雅关闭 |
| HTTP | Gin | REST `/api/*`，静态资源 `/`、`/assets`、`/uploads` |
| 存储 | SQLite（WAL） | DSN 带 `_busy_timeout=5000`；表结构与迁移在 `internal/store` |
| 认证 | JWT（HS256，24h） | claims: user_id/username/role/family_id/is_admin |
| 定时 | 内置 goroutine 调度器 | 健康同步/日历同步/AI 分析/周末推荐/提醒/推送/清理 |
| 外部进程 | 3 个 MCP server（Go）+ 2 个 Python 同步脚本 | MCP 能力当前以独立进程形态存在；脚本经调度器调用直写 SQLite |
| 前端 | 静态 HTML/PWA（`web/`） | 由 Go 直接托管，非独立 Node 服务 |

> 与旧 PRD 的差异订正：数据库是 **SQLite 而非 PostgreSQL**；配置文件是 **config.yaml + HOMEMATE_* 环境变量**而非 .env；入口是 `cmd/homemate`；前端无独立 3000 端口。

## 3. 角色与权限模型

### 3.1 两套身份

1. **登录账号 users**：`role ∈ {admin, adult, child, elder, guest, pet}`，其中 `admin` 为系统管理员账号（不对应家庭成员）。
2. **家庭成员 family_members**：家庭角色 `{adult, child, elder, guest, pet}`（admin 不是家庭角色），`is_admin` 标记被委派的系统管理员；通过 `user_id` 关联登录账号。

### 3.2 鉴权三级

| 级别 | 挂载方式 | 代表接口 |
|------|----------|----------|
| 公开 | 无中间件 | `POST /api/auth/login`、`GET /api/chorse/dashboard`、`GET /api/dashboard/bigscreen`、`GET /api/news`、`GET /api/anniversaries`、`GET /api/chat/ws` |
| 登录用户 | AuthMiddleware（JWT） | 绝大多数业务接口 |
| 系统管理员 | RequireAdmin() | 成员增删改、任务/新闻/方案管理、调度器配置、API Token、归档查询、企业微信配置 |
| 外部集成 | APITokenAuth(scope) | `/api/external/news`、`/api/external/anniversaries`、`/api/external/weekend/proposals`、`/api/external/calendar/events` |

### 3.3 身份绑定规则（v4.0 强化，范式 §2.2）

- 业务身份（认领人、投票人、兑换人、确认人）一律由后端从 JWT → family_members 解析，**请求体中的 member_id/member_name/confirmer 不再作为身份依据**。
- 未绑定家庭成员的账号调用家庭业务接口返回 403。
- 管理员代操作走独立管理员接口。
- 用户自助注册 `POST /api/auth/register` 收归 **RequireAdmin**（首个管理员由种子账号 admin/admin123 引导，部署后必须改密）。

## 4. 核心业务与状态机

### 4.1 家务协作（chorse）

- 任务库 chorse_tasks（admin 维护，软删除 is_active）：难度 简单/中等/困难，对应积分分类标签。
- 认领 chorse_claims 状态机：

```
pending ──完成──▶ completed ──验收人确认──▶ confirmed（同事务写积分流水）
   │                  └──（仅验收人本人或管理员可确认，身份取自 JWT）
   └── 幂等：同一成员对同一任务存在 pending/completed 认领时禁止重复认领
```

- 自动指派验收人：首个非执行人的成人；家庭仅一人时允许自验收。
- 认领时任务名称/图标/积分以**服务端任务库为准**，前端传值仅作 fallback 校验。

### 4.2 积分与兑换

- points_records 为**流水表**：`points` 可正可负；`pts_type ∈ {chorse, redeem, ...}`，`type_label` 对家务为难度（简单/中等/困难）。
- 余额/排行 = 流水求和（含负向）；等级阈值：新手 0 → 全能小能手 500 → 活力达人 2500 → 运动健将 3000 → 传奇管家 4000。
- 兑换 redeem_records 状态机：

```
pending ──管理员确认(confirmed)──▶ 同事务写 -cost 积分流水；余额不足拒绝
        └─管理员驳回(rejected)──▶ 不扣分
仅允许 pending → confirmed/rejected，重复迁移返回 409
```

- 积分流水属用户资产，**不进入历史清理 TTL**。

### 4.3 周末休闲

- 方案库 weekend_proposals（可 CSV 导入）；投票 weekend_votes 有 `UNIQUE(proposal_id, member_id)`，每个成员同时只投一个方案（取消票按 member_id 删本人票）。
- 投票/取消身份取自 JWT；`GET /weekend/dashboard` 返回方案、票型结果、winning 标记。
- 调度器每周四 19:00 生成离线推荐缓存（weekend_recommendation，AI 推荐为规划中）。

### 4.4 日历与提醒

- 事件 calendar_events：支持周期规则（recurrence_rule）、提醒提前量（reminder_minutes）、Apple 日历外部事件（source/source_account/external_event_id 唯一索引去重）。
- 提醒链路：调度器每分钟扫描 → 到点生成 notifications → 通知推送任务经企业微信 webhook 下发。
- 时间输入统一按本地时区解析（ParseInLocation）。

### 4.5 健康数据

- health_data_cache：按 (member_id, date) 唯一，覆盖 Garmin 30 项指标（步数/心率/睡眠/压力/血氧/身体电量/HRV 等）。
- 数据源配置 data_source_config：每成员每类数据源唯一；凭证接口返回脱敏；脚本同步模式（use_script_sync）经 Python garth 登录直写 SQLite。
- 健康档案 health_record_files：PDF/图片上传（50MB 上限、扩展名校验、文件名 hash 化），AI 分析为规划中能力（当前不生成模板报告）。

## 5. 调度器任务

| 任务 | 默认间隔 | 说明 | 配置热生效 |
|------|----------|------|-----------|
| health_sync | 6h | Garmin 健康同步（脚本/Go 双模式） | 启停+间隔 |
| calendar_sync | 1h | Apple 日历同步（仅 macOS，需 TCC 授权） | 启停+间隔 |
| ai_analysis | 每日 08:00 | 档案 AI 分析（规划中，当前不产报告） | 启停 |
| weekend_recommend | 每周四 19:00 | 离线周末推荐 | 启停 |
| reminder_scan | 5m | 到期提醒生成通知 | 启停 |
| notification_push | 1m | 未推送通知经 WeCom 下发 | 启停 |
| calendar_reminder | 1m | 日程到点提醒 | 启停 |
| cleanup | 每日 03:00 | 时效数据归档（news 30d/通知 90d/聊天 365d/留言 180d/设备 90d；积分不清理） | 启停 |

- 任务状态接口 `GET /api/scheduler/status` 如实返回 last_run/last_status/next_run；执行结果以真实成败记录。
- 配置接口 `PUT /api/scheduler/config`（管理员）：启停立即生效，间隔立即生效。

## 6. 外部集成

- **API Token**：api_tokens 表存 hash + scopes，`/api/external/*` 按 scope 鉴权（news:write / anniversary:write / weekend:write / calendar:write）。
- **企业微信**：群机器人 webhook 推送；配置可运行时修改且对调度器即时生效；`PUT /api/wecom/test-push` 自测。
- **微信公众号回调**：`POST /api/wechat/callback`，配置 Token 时校验签名；消息回复当前为占位。
- **MCP server**：weather-mcp / health-mcp / garmin-mcp 独立进程，stdio 传输（工具契约见 README）。

## 7. 非功能约定

- 时间：本地时区存储与解析；详见范式 §2.4。
- 数据：关联一律用 ID（v4.0 起 points_records/redeem_records 增加 member_id 并回填，名字仅冗余展示）。
- 安全：注册管理员化、业务身份 JWT 化、上传文件名 Base 化、密钥脱敏、默认口令引导改密。
- 可观测：调度日志统一 `[SCHEDULER]` 前缀；失败不静默。
- 提交：Conventional Commits + 每任务 build/vet/commit/push。

## 8. 规划中（Roadmap，不在 v4.0 交付）

- AI 对话接入真实大模型（当前 chat 为回声占位）与健康档案 AI 分析报告。
- MCP 客户端在主服务内接线（当前 MCP server 独立运行）。
- 成员删除的关联数据处置策略（users 账号解绑/归档）。
- 登录锁定改按 IP+账号双维度，避免被恶意锁死。
- 微信绑定落库（当前 bind 为占位）。
