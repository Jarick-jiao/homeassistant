## 一、修复报告

本轮共 8 项修复/增强，每项含「修复点 / 根因 / 验证方式」三段。

### 1. 宠物角色全链路支持

- **修复点**：新增 `RolePet` 角色常量，贯通 model → handler 校验 → middleware 权限 → dashboard 统计 → 前端表单选项。
  - `internal/model/models.go`：新增 `RolePet = "pet"` 常量
  - `internal/handler/member/handler.go`：`validRoles` 加入 `pet`
  - `internal/router/middleware/role.go`：`RolePet` 权限等同 guest（最小权限）
  - `internal/handler/dashboard/handler.go`：统计 case 补 `RolePet`
- **根因**：家庭场景需将宠物作为独立成员角色管理（喂养/健康记录），旧角色体系仅含 parent/child/guest，无法表达。
- **验证方式**：`go build ./...` + `go vet ./...` 通过；前端成员表单可选「宠物」。
- **提交**：`694027f`

---

### 2. 调度器状态不显示完整任务列表

- **修复点**：调度器新增 `taskRegistry` 任务注册表，`Status()` 遍历注册表返回全部任务（含从未执行过的任务），并补充 `last_run` / `last_status` / `next_run` 字段。
  - `internal/service/scheduler/scheduler.go`：`Scheduler` 增加 `taskRegistry []taskMeta` 与 `lastStatus map[string]string`；`recordRun()` 统一记录时间+状态；`Start()` 构建注册表；`Status()` 返回完整列表。
- **根因**：旧 `Status()` 仅遍历 `lastRuns` map，从未触发的任务不会出现，前端面板看不到 AI 分析、周末推荐等定点任务。
- **验证方式**：`GET /api/scheduler/status` 返回 8 个任务条目；前端调度器面板渲染完整列表。
- **提交**：`694027f`、`96353ea`（补 `interval` 字段）

---

### 3. 数据源配置编辑变新增（重复行）

- **修复点**：三层修复确保每个成员同一数据源类型仅保留一条配置。
  - **应用层**（`694027f`）：`SaveDataSourceConfig` 改为 UPSERT — 先 `SELECT id WHERE member_id=? AND source_type=?`，命中则 `UPDATE`，否则 `INSERT`；前端 `editDataSource` 回填现有配置。
  - **DB 层**（`d6d39b0`）：`migrate()` 自动清理 `(member_id, source_type)` 重复行（保留 `MAX(id)`），新建唯一索引 `idx_data_source_config_member_type`。
  - **运维层**：新增 `scripts/cleanup_duplicate_data_sources.sql` 供生产库手动执行；`scripts/init_db.sql` 同步表定义与索引。
- **根因**：旧版 `SaveDataSourceConfig` 为纯 `INSERT`，每次编辑成员数据源都新增一行，导致同一 `(member_id, source_type)` 存在多条记录，调度器遍历时重复同步、前端列表重复。
- **验证方式**：`go test ./internal/service/scheduler/...` 通过（InitDB 执行 migrate 含新索引创建）；手动 `INSERT` 同一 `(member_id, source_type)` 第二次报 `UNIQUE constraint failed`；前端编辑 → 提交 → 列表无新增重复。
- **提交**：`694027f`、`96353ea`、`d6d39b0`

---

### 4. Garmin 同步脚本版本检测崩溃

- **修复点**：`scripts/homemate_health_sync.py` 用 `importlib.metadata.version("garminconnect")` 可靠检测版本，替代坏掉的 `getattr(__version__, "0")` 字符串比较。
- **根因**：新版 `garminconnect` 不再暴露 `__version__` 属性，旧代码 `getattr(..., "0")` 得到字符串 `"0"`，与 `"0.3.0"` 比较后误报版本过低，进入 `prompt_mfa` 分支抛 `TypeError` 崩溃。
- **验证方式**：脚本启动时正确打印 `garminconnect` 实际版本号，不再误报；无 `TypeError`。
- **提交**：`694027f`

---

### 5. 日历同步脚本 dateutil 缺失崩溃

- **修复点**：`scripts/homemate_calendar_sync.py` 将 AppleScript 频率 → dateutil 频率映射 `_build_freq_map()` 移入函数内部按需构建（`HAS_DATEUTIL` 为 false 时返回空 dict）。
- **根因**：模块级直接引用 `DAILY`/`WEEKLY` 等常量，当 `python-dateutil` 未安装时这些名称未定义，`import` 阶段即 `NameError` 导致脚本整体崩溃，而非预期的「缺失则跳过循环展开」优雅降级。
- **验证方式**：未安装 dateutil 时脚本正常退出（跳过循环展开，仅同步原始事件）；安装后正常展开循环事件。
- **提交**：`c13c115`

### 6. 成员表单缺宠物角色选项

- **修复点**：`web/index.html` 成员表单角色 `<select>` 新增 `pet`（宠物）选项。
- **根因**：后端已支持 `RolePet`，但前端表单未提供该选项，用户无法新建宠物成员。
- **验证方式**：成员表单角色下拉可见「宠物」选项并可选中保存。
- **提交**：`c13c115`

---

### 7. Agent 工作流强制规则

- **修复点**：新增 `.trae/rules/agent-workflow.md` 项目级 Agent 规则，固化代码修改收尾流程 `go build → go vet → git add → git commit → git push`；README.md 开发规范章节追加引用。
- **根因**：此前修改存在「仅 commit 不 push」「build/vet 未跑即提交」等流程缺失，导致远程仓库与本地不一致、未通过静态检查的代码入库。
- **验证方式**：规则文件存在且内容完整；本轮任务2/3 已按规则执行 build+vet+commit+push。
- **提交**：`63872b0`

---

### 8. 调度器状态页分页 + 编辑控制

- **修复点**：
  - **后端**：新增 `UpdateTaskConfig(task, enabled, interval)` 持久化到 `family_settings`；`isTaskEnabled()` 供各 `run*` 方法开头检查（启停立即生效）；`Start()` 启动时 `loadTaskConfigOverrides` 读取 settings 覆盖（health_sync 间隔即时生效，其余重启生效）；`Status()` 补 `interval` 字段；注册 `PUT /api/admin/scheduler/config`。
  - **前端**：`loadSchedulerStatus` 分页渲染，每页最多 5 个任务；新增编辑弹框（启用开关 + 间隔输入），定点任务（ai_analysis/weekend_recommend）禁用间隔；翻页按钮边界 disabled。
- **根因**：调度器任务无法在前端启停或调整间隔；任务超过 5 个时面板过长不易浏览。
- **验证方式**：见下方测试报告；8 任务分 2 页（5+3），分页边界正确；`PUT config` 后 `GET status` 反映变更。
- **提交**：`96353ea`
